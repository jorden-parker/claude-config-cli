### 1. Failed-load write protection

`store.Open` returns a `File` alongside parse errors. Ordinary form submission, cycling, and removal save that file without consulting `m.errs`; the environment/tool paths already check it. A malformed document can therefore be replaced by an empty or partially decoded map. JSON `null` is also accepted as a successful load, leaving a nil map that `Set` writes into.

Reject non-object/null documents and prevent every mutation of a scope that failed to load. Tests should cover all three ordinary edit paths and prove original bytes remain unchanged. Keep missing-file creation distinct from invalid-file handling. The low fix risk assumes empty-file behavior is explicitly preserved or decided.

### 2. Activation bypasses the preview execution gate

`statusTrusted` and `statusPreview` prevent automatic execution of project/local commands. Activation saves the inherited command into the companion file, then `statusCheck` invokes the renderer, which executes that command. This happens without pressing the documented `p` preview action, including when user settings inherit a project command. The existing consent test at `internal/tui/status_test.go:194` tests startup and `p`; activation tests replace the production check with a no-op at `internal/tui/status_test.go:32`.

Separate renderer validation from inherited-command execution and retain command origin/consent when wrapping it. This is a mismatch with the explicit preview promise, not a claim that configured shell execution is inherently a vulnerability. Validate without running the inherited command, or make activation's execution consent explicit and consistent. Cover the real activation chain with harmless fixtures. Move potentially blocking validation into a `tea.Cmd`: the current synchronous call at `internal/tui/status.go:250` can stall the event loop for roughly three seconds plus the 200 ms pipe wait. This related performance change belongs in the same plan, with scope-aware completion handling.

### 3. Schema generation is not preserving its input contracts

Two defects need one ordered generator repair. The extractor recognizes only `*` metadata bullets while checked-in references use `-`. Running only its computation reproduced 243 missing types/scopes. `gen.py` defaults missing scopes to `any` and writes output before its final tools-catalogue check. This is a defect when regenerating from checked-in inputs; it does not establish that every fresh network download uses the failing format.

Independently, `classify` checks quoted options before root container types. The current schema classifies `spinnerVerbs`, `voice`, `skillOverrides`, `sandbox.credentials.sigv4`, and `allowedProviders` as scalar enums although their own type descriptions say object/array. Valid object input is rejected and scalar picker values are invalid shapes.

First add Markdown fixture tests, required-metadata validation, and validation-before-output publication. Then classify containers before member options and regenerate. Add example-based assertions for all five entries. Existing `internal/value/value_test.go:61` checks catalogue size and superficial completeness, so it misses both defects. Avoid broad changes to hand-curated aliases or arbitrary JSON validation.

### 4. Atomic persistence

Both store and statusline saves use `os.WriteFile` on the live destination. A failed/interrupted write can damage original bytes even though the caller reports failure. Forced snapshot restore already demonstrates same-directory temporary-file replacement at `internal/snapshot/snapshot.go:184`.

Introduce a shared replacement primitive with explicit mode and symlink behavior; write and close successfully before replacing. Decide the durability requirement, including whether syncing is needed. Test write/close/replace failures and preservation of the original file. Atomic replacement alone does not resolve stale writers (#5), failed in-memory mutations (#8), or transactionality across the settings and companion files.

### 5. External-change conflict detection

The TUI loads all files at startup/manual reload. `afterWrite` refreshes rows and status information but does not reload settings. `File.Save` serializes the entire loaded map without checking whether the on-disk file changed. A second Claude process or editor can add a setting after the TUI opens; saving an unrelated field removes that newer addition.

Define an explicit conflict policy at the persistence boundary. A detected conflict with a reload prompt is safer and easier to verify than an implicit merge. Address the check-to-replace race rather than claiming an unlocked timestamp check is fully safe. Cover two independently loaded writers and deletion/recreation of a destination. Extend the policy to long-lived companion configuration. This is separate from Go data races, so passing `-race` does not test it.

### 6. Lossless editor round trips

`Text` joins arrays with newlines; `parseArray` interprets a single-line value as comma-separated. One stored item containing a comma becomes multiple items merely by reopening and saving. Empty items, whitespace, and embedded newlines are also lossy. Map text similarly joins raw values into lines and then trims them; multiline string values cannot reliably round-trip. Dedicated environment-variable editing preserves strings, but editing the whole `env` map uses the generic path.

Use unambiguous JSON for values that cannot safely use the friendly representation, or separate editor parsing from CLI comma shorthand. Test `Text → Parse` equivalence and actual editor completion. Preserve documented CLI shorthand rather than removing it incidentally.

### 7. Active configuration root

`store.Path` always chooses `~/.claude/settings.json`; snapshot and companion paths derive from it. It does not read an exported `CLAUDE_CONFIG_DIR`, although the bundled environment catalogue describes that override. The current official [environment reference](https://code.claude.com/docs/en/env-vars) confirms that the variable redirects the configuration directory. Consequently a custom-root user can edit or snapshot the default account's files instead of the active configuration.

Centralize configuration-root resolution for settings, companions, paths display, and snapshots. Verify the exact global `.claude.json` placement for the supported Claude version before changing it; that placement is not established by this audit. Test unset, absolute, relative, and empty overrides, and clarify precedence without recursively treating arbitrary project `env` contents as configuration-root authority.

### 8. Commit in-memory changes only after persistence succeeds

Ordinary edits mutate `m.files` before `Save`; status field/placement/color changes mutate `m.sl.cfg` before saving. Failed changes remain in memory and may be written by a later unrelated successful edit. The specialized environment/tool staging paths show the intended safer pattern, but copy logic is repeated and can lose numeric precision (#9).

Create a consistent staged mutation boundary and publish the new model state only after success. Deep-copy nested maps and slices; preserve key-order metadata and numeric representation. Test a failed edit followed by a successful unrelated edit, not only the first error message. Coordinate with #1, #4, and #5 instead of independently refactoring the same save paths.

### 9. Persist numbers without float64 conversion

Ordinary JSON decoding into `any` turns numbers into float64. Any later save can round unrelated large integers and precise decimals. JSON-based TUI cloning repeats this conversion. Snapshot raw-byte preservation already tests a large integer at `internal/snapshot/snapshot_test.go:33`, but ordinary edits lack the equivalent guarantee.

Use a number-preserving decoder and cloning strategy, and inspect numeric consumers before changing representation. Test unrelated-field edits in CLI and specialized TUI paths. This preserves existing stored numbers; #10 governs new numeric input.

### 10. Validation contracts differ by input syntax

The number parser checks only `ParseFloat`, then converts integral floats to `int64` without checking representable range. It does not enforce documented integrality/ranges or exclude nonfinite values at the input boundary. The JSON route for `map-bool` accepts arbitrary values while line syntax checks each Boolean. For example, the bundled `skillListingBudgetFraction` contract is greater than zero and at most one (`tools/ref.md:2987`).

Add evidenced numeric constraints to schema metadata and apply the same typed-map validation after both parsing routes. Reject nonfinite/out-of-range input before conversion; test that rejection leaves disk unchanged. Keep arbitrary JSON settings open unless their contracts have been explicitly modeled. Repair generation (#3) before adding constraint metadata.

### 11. Preview/check working directory

`-C` changes the path returned by `cwd()` but does not change process cwd. `RunInherited` never sets `cmd.Dir`, so passing a sample session containing another project path does not make relative scripts run there. Preview/check can fail or report the launch repository.

Pass an explicit normalized execution directory for preview/check operations and test while launched outside the selected project. Keep actual renderer semantics deliberate; do not silently change every execution mode merely because they share a helper. Coordinate this change with #2.

### 12. Tool validation can report a false pass

The entire Claude/grep pipeline is followed by `|| true`; any failure without a matching permission warning reaches the success message. Authentication failure, missing executable, or a failed request therefore does not establish validation, yet the script reports that every tool name is accepted.

Capture the command's exit status separately from diagnostic filtering, and distinguish a failed validation run from an invalid tool name. Test with stub executables rather than paid/authenticated network calls. Do not run the real tool checker in ordinary unit tests.

### 13. Snapshot destination aliases

Restore deduplicates absolute path strings, not their physical destinations. A symlinked parent can make project/user scopes address the same file. With no force, both pass preflight while absent, then the second write fails after the first succeeds. With conflicting contents and force, randomized map iteration chooses the final contents. The current alias test covers only identical lexical paths.

Canonicalize existing ancestors, handle absent descendants, deduplicate identical contents, and reject conflicting aliases before writing. Add symlink-parent tests. Retain documented partial success for genuine later I/O failures; that behavior is intentional. This finding concerns the uncommitted snapshot feature and should be checked before shipping it.
